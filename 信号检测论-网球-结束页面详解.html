0三十秒速览

问题答案
d′ 由谁控制？ 游戏。四个旋钮：落点离线距离 clearBias、视觉抖动幅度 noise、 飞行时长 T、球的可见度 ballA。三档难度就是把这四个旋钮拧到不同位置。
β 由谁控制？ 你自己。游戏不设定 β，也没有收益矩阵；β 是同一份 H / FA 数据里顺带解出来的 反应偏向，是果不是因。
三档差在哪？ 明显球占比 86% / 57% / 24%， 抖动振幅 2.2 / 4.5 / 8.9 px， 反应窗 1.95 / 1.75 / 1.45 s。
最关键的一点 界内球和界外球的落点分布根本不重叠（最小离线 5 cm / 6 cm）。 所以 d′ 不是被「落点重叠」限制的，而是被知觉噪声限制的—— 一个能准确读出落点的观察者，d′ 是无穷大。

1结果页的数据流

1.1 从 12 球到 2×2 四格

一轮固定 12 球：6 个界内球（信号）、4 个界外球 + 2 个空发球（噪音）。 界外球和空发球都算噪音，所以 nN = 4 + 2 = 6，与 nS = 6 配平。

四格映射（源码 resolve()）
你挥拍了
报告「有信号」		 你没挥拍
报告「无信号」
界内球（信号） 击中 H 漏报 M
界外球 / 空发球（噪音） 虚报 FA 正确拒绝 CR

1.2 四格到四个指标

P(H) = H / 6 P(FA) = FA / 6 d′ = z(H) − z(FA) ← 辨别力（敏感度） c = −½ · [ z(H) + z(FA) ] ← 判定标准（标准分刻度） β = exp{ [ z(FA)² − z(H)² ] / 2 } ← 似然比（比值刻度） A′ = Grier 非参数 ROC 面积 ← 不依赖正态假设的备选

其中 z() 是标准正态分布的逆函数（源码用 Acklam 算法实现 zInv()）。 结果页上 d′ 是能力，c 和 β 是偏向，A′ 是能力的非参数版本。

1.3 零格校正：为什么你的 d′ 永远不可能是 ∞

如果某一格是 0，z() 会发散成 ±∞。所以源码里有个开关：

clean = (H > 0 && M > 0 && FA > 0 && CR > 0) clean ? 直接用原始比例 P(H)=H/6, P(FA)=FA/6 : 用 0.5 对数线性校正（Hautus 1995） hh = (H + 0.5) / (nS + 1) = (H + 0.5) / 7 ff = (FA + 0.5) / (nN + 1) = (FA + 0.5) / 7

四格全非零时，结果页底部会显示「各格均非 0，指标无需校正」；出现 0 格则显示 「本次 H/M/FA/CR 中有 0 格，d′ 等指标已用 0.5 对数线性校正估算」。

这带来一个必须知道的天花板

打出满分 6/6（H=6, M=0, FA=0, CR=6）时，校正给出 hh = 6.5/7 = 0.9286、 ff = 0.5/7 = 0.0714，于是

d′ = 1.4652 − (−1.4652) = 2.930

也就是说：单轮 d′ 的取值被硬夹在 [−2.93, +2.93] 之间。哪怕你知觉完美， 结果页也不会出现比 2.93 更大的数。看到 2.93 就等于「这轮全对」， 而不是「我的 d′ 刚好是 2.93」。

2d′ 敏感度是如何被控制的

2.1 前提：两个落点分布根本不重叠

球的落点由 buildTrials() 生成，BN = −11.885 是近端底线：

界内球： landZ = BN + m m ∈ [0.05, 3.60] （离线 m 米在界内） 界外球： landZ = BN − m m ∈ [0.06, 1.45] （离线 m 米在界外） 空发球： 不生成球

界内球最贴近底线也有 5 cm 余量，界外球最近也有 6 cm。 两个分布之间有一道真空带——没有任何一个球落在离底线 ±5 cm 以内。

结论：d′ 不来自「落点重叠」

一个能准确读出落点的观察者永远不可能错，它的 d′ 是无穷大， 三档难度对它没有任何区别。所以本作的 d′ 完全来自「你看不清落点」这件事。 难度参数不是在制造信号与噪音的重叠，而是在决定你要看清到什么程度才够用。

2.2 于是：d′ ≈ 离线距离 ÷ 知觉噪声

设玩家从球的飞行中估计落点，估计误差服从 N(0, σ)（单位：米）， 然后按「估计落点是否越过底线」决定挥拍。对离线 m 米的球：

界内球被判「界内」的概率 = Φ( m / σ) 界外球被判「界内」的概率 = Φ(−m / σ) = 1 − Φ(m / σ)

代入三档各自的离线分布，同一个 σ 下三种难度的期望 d′ 如下 （已计入 2 个空发球试次、按 25% 误报率计）：

σ（落点估计误差）0.3 m0.5 m0.75 m1.0 m1.25 m1.5 m2.0 m3.0 m

读法：一个 σ = 1.0 m 的玩家，在简单档能打出 d′ ≈ 2.4，换到困难档只剩 1.3。

这就是「敏感度被控制」的直接证据

同一个玩家，换个难度，结果页上的 d′ 就变了。 所以 d′ 在结果页上衡量的是「你 + 这一档难度」的联合表现，而不是你的固有属性。 跨难度比较自己时，请记住这一点。

旋钮 ①　clearBias —— 落点离线多远（主旋钮）

每个球先掷一次骰子决定走「明显」还是「模糊」分支：

明显界内： m ~ U(1.10, 3.60) 模糊界内： m ~ U(0.05, 1.10) 明显界外： m ~ U(0.85, 1.45) 模糊界外： m ~ U(0.06, 0.85)

色块宽度 = 该分支的离线区间；色块浓淡 = 该分支被抽中的概率（不透明度即概率）。灰阶越浓表示越多球落在这里。

注意一个不对称：明显界内最远能到 3.60 m，明显界外最远只有 1.45 m。 也就是「一眼就看出是界内」的球，比「一眼就看出是界外」的球明显得多。

三件必须注意的事

  1. 双重放大。抖动振幅随球速增大，而困难档的 T 更短 ⇒ 球更快。 所以困难档相对简单档是 noise 大 3.07 倍 × 球速高 1.43 倍 ≈ 4 倍的抖动。 两个旋钮（noise 和 T）在这里是耦合的。
  2. 盯着看也平均不掉。抖动里有 0.25·N(0,1) 这一项是逐帧白噪声， 每秒重新抽 60 次。想靠长时间注视把噪点平均掉是无效的—— 只有 sin／cos 那两个低频摆动项在时间上是平滑的。
  3. 抖动是屏幕像素常量，不随景深缩放。代码把 jx/jy 直接加在投影后的像素坐标上， 而球的像素半径是 FOC·BALL_R/depth，会随距离变小。 结果是：球在远处（像素半径小）时，相对抖动更严重。 这是实现层面的副作用，不是刻意设计——但也算给"提前预判"加了点惩罚。

旋钮 ③　T —— 飞行时长 = 反应窗长度

T 一鱼三吃：

  • 它是反应窗长度——swing() 里 if (G.t >= G.T) return;，球落地那一帧窗就关了，之后按空格无效。
  • 它决定球速——vz = (landZ − z0) / T，T 越短球越快。
  • 于是它通过旋钮 ② 的 sp 项放大视觉抖动。

三档的预备期都固定 0.75 s（if (G.preT >= 0.75) beginFlight()），没有难度差异。

旋钮 ④　ballA —— 球的可见度

作用于球体渐变、光晕和地面影子三处的不透明度。困难档的球和影子都淡 8%。 影响幅度不大，属于陪衬性的难度调节。

2.4 三个「不能用」的线索

设计得当的地方在于：球身上其实还带着三个看起来有用、实际无用的线索。

线索为什么没用
横向落点 landX landX ~ U(−3.2, 3.2)，永远落在单打边线（±4.115）以内。 左右方向不携带任何「界内 / 界外」信息——只有纵深 z 方向的落点才是判据。
来球角度 起手点 x0 = landX×0.45 + U(±1.2)，额外加了随机量， 没法从来球方向反推落点。
「这球发没发」 2 个空发球试次的预备时长、节奏条长度、发球提示音与其他试次完全一致 （源码注释：「所有试次时长一致，不泄露是球还是空发球」）。 所以空发球只能靠眼睛发现「球没出现」，不能靠节奏提前预判。

3β 是如何体现的

3.1 β 是玩家的，不是游戏的

DIFF 里没有任何一项和 β 有关。回顾一下因果方向：

游戏难度参数（DIFF） → 决定 d′ 的可及范围 → 你的 H / FA 分布 ↓ 同一份 H / FA 数据里，同时解出 d′（能力）与 β、c（偏向）

d′ 是被操控的自变量，β 是顺带观测到的因变量。 游戏没有提供任何手段去"设置"你的 β——它只能通过难度间接影响你， 而你对 β 的贡献是完全自主的。

3.2 β 的读数

β = exp{ [ z(FA)² − z(H)² ] / 2 }
读数含义结果页上的文案
β > 1保守：要求足够强的证据才挥拍倾向放掉，代价是漏报多
β = 1中立：无偏向比较中性
β < 1冒进：证据不强也挥倾向挥拍，代价是虚报多

β 的绝对值很好懂：β = 2 就是「我认为界内的先验几率要达到 2 : 1，我才挥拍」。

3.3 β 在 ROC 图上的位置

结果页右下角那张 ROC 图同时编码了 d′ 和 β，读法如下：

图元含义
灰色虚线对角线瞎猜（d′ = 0）。落在对角线附近 ⇒ 这轮基本靠猜。
蓝色曲线用你这轮的 d′ 拟合出的等方差 ROC。 曲线离对角线多远 = d′。
● 红色实测点你的 (P(FA), P(H))。 点在曲线上滑到哪个位置 = β。越靠左上角，β 越大。

所以这张图是「一条曲线 + 曲线上一个点」：曲线形状说能力，点的位置说偏向。 两个玩家可以有完全相同的 d′（曲线重合），但落在曲线上的不同位置（β 不同）。

3.4 关键：β = exp(d′ · c)，所以 β 不能跨难度比较

在本作的等方差正态模型下，结果页上的三个指标严格满足一个恒等式：

β = exp( d′ · c ) 证明：d′·c = (zH − zF) · [−½(zH + zF)] = −½(zH² − zF²) = ½(zF² − zH²) ∎

用源码的 computeStats() 遍历全部 7 × 7 = 49 种可能的 (H, FA) 组合验证， 最大偏差 8.9e-16，即浮点误差。这个恒等式是精确成立的。

推论：β 同时被 d′ 和 c 决定，只有 c 是跨难度可比的

同样一个「偏保守」的态度（c 相同），在你分辨力更高的时候会表现为更大的 β：

判定标准 cd′ = 1 时的 βd′ = 2 时的 βd′ = 3 时的 β
+0.5（偏保守）1.652.724.48
0（中立）1.001.001.00
−0.5（偏冒进）0.610.370.22

所以想比较「我今天在简单档和困难档哪个更敢挥」，请比 c，不要比 β。 c 是标准分刻度上的绝对位置，与 d′ 无关；β 是似然比刻度，与 d′ 纠缠在一起。

3.5 空发球：β 的专用探针

每轮 2 个空发球试次，根本没有球，正确答案永远是「不挥」。 挥了就是虚报。这是唯一一个与 d′ 完全无关的偏向读数：

  • 对空发球产生 FA ⇒ 你的标准低到了「没信号也挥」的程度。
  • 它让 nN = 4 + 2 = 6，使 P(FA) 不完全由真实存在的界外球决定。
  • 一个从不挥拍的玩家：P(H) = 0、P(FA) = 0 ⇒ d′ = 0、A′ = 0.5、c = +1.465（极度保守）。 结果页会显示 d′=0 而 c 很大——这正是「毫无分辨力、且极度保守」的画像。

3.6 本作没有收益矩阵 ⇒ 没有「最优 β」

一个诚实的说明

代码里没有计分：H、M、FA、CR 各记 1 次，没有得失分权重。 因此：

  • 数学上的「中立」标准是 c = 0（β = 1），不是某个最优值。
  • 结果页文案里的「漏报就是直接丢分」「挥空」是叙事，不参与任何计算。
  • 如果要做真正的「最优决策」教学，需要引入收益矩阵（击中收益 V、虚报代价 K 等）， 此时最优标准为 β_opt = P(N)/P(S) × (V_CR + V_FA) / (V_H + V_M)。 本作有意省略了这一层。

3.7 结果页把 β 和 d′ 翻译成了什么汉字

先看 d′ 的档位：

d′ 区间文案
d′ < 0.6几乎分不出界内界外
0.6 ≤ d′ < 1.5有一定分辨力
1.5 ≤ d′ < 2.5分辨力不错
d′ ≥ 2.5分辨力相当强

再看 偏向——注意这里判的是 c 而不是 β：

c 区间文案
c < −0.15偏冒进——你倾向于挥拍，代价是虚报多
−0.15 ≤ c ≤ +0.15比较中性——不怎么偏
c > +0.15偏保守——你宁可放掉也不挥空，代价是漏报多

最后按顺序追加一句建议，只看第一条命中的（源码里的 if / else if 链）：

序触发条件追加文案
1P(H) > 0.9 且 P(FA) < 0.1又准又稳，这轮打得很干净
2P(FA) > 0.5虚报偏多：下次先看清球有没有发出来、过没过底线
3P(H) < 0.5漏报偏多：判断「可能进」时不妨打
4其余这个偏向配上你的 d′，就是你在本轮里的最优策略

第 4 条文案与 3.6 节有张力

「最优策略」这个说法隐含了某个收益结构，但代码里并没有收益矩阵。 更严谨的表述是：「在无记分的前提下，你这一轮采用的偏向是自洽的」。 如果这是要给别人看的教学演示，建议把这条文案改掉，或明确加上收益假设。

4.2 一句话概括每一档

简单 easy　—— 教学档

85% 的球明显离线（界内平均离线 2.1 m），抖动只有 2.2 px，给你 1.95 s。 普通玩家也能打出 d′ > 2，第一次接触 SDT 时容易建立「界内 / 界外确实分得开」的直觉。

普通 normal　—— 默认档

一半明显一半贴线，抖动 4.5 px，1.75 s。σ = 1.0 的玩家 d′ ≈ 1.8， 落在「分辨力不错」的区间下沿。结果页默认选中这一档。

困难 hard　—— 逼近阈限

只有 24% 的球明显，80% 的球离线不到 1.1 m，抖动 8.9 px（简单档的 4 倍），只有 1.45 s。 σ = 1.0 的玩家 d′ ≈ 1.3，几乎贴到「有一定分辨力」的下限。 真正能拉开差距的是那些贴线的球——它们要求你从一团抖动的像素里挤出落点估计。

5.1 十二球的精度警告

单轮 d′ 的噪声有多大

12 个信号 + 12 个噪音的样本量很小。实测（σ = 1.0 的固定玩家，3000 轮）： 逐轮 d′ 的标准差约 0.55 ~ 0.71。

也就是说：两轮之间 d′ 差 0.5，完全说明不了任何问题。 要看到真实的难度效应或进步，至少需要看 10 轮以上的平均，或者干脆把 NTRIAL 从 12 提到 40+。

另一个坑：逐轮 d′ 的均值 ≠ 汇总比例的 d′。 因为 d′ 是比例的非线性函数，先算 d′ 再平均会偏低（简单档实测 2.08 vs 汇总值 2.37）。 结果页给的是单轮 d′，天生有偏且噪声大——这一点在教学时值得挑明。

7备忘卡

关于 d′

  • 界内 / 界外落点分布不重叠（最小离线 5 cm / 6 cm）⇒ 完美观察者 d′ = ∞。
  • d′ 的高低 ≈ 离线距离 ÷ 知觉噪声。
  • 四个旋钮：clearBias（离线多远）、noise（抖多少）、 T（窗多长，且耦合放大抖动）、ballA（球多亮）。
  • 同一玩家换难度，d′ 就变 ⇒ d′ 是「你 + 难度」的联合量。
  • 单轮 d′ 被 0.5 校正夹在 [−2.93, +2.93]；2.93 = 全对。
  • 单轮 d′ 的抽样噪声 ≈ ±0.6，别拿两轮比较。

关于 β 和 c

  • β 不是游戏设的，是你按出来的。d′ 是自变量，β 是因变量。
  • β = exp(d′ · c)，精确成立（49 格验证，误差 8.9e-16）。
  • 因此 β 跨难度不可比；要比较自己的偏向，看 c。
  • ROC 图：曲线离对角线多远 = d′；点在曲线上滑到哪 = β。
  • 空发球试次是 β 的专用探针（无球也挥 = 标准太低）。
  • 没有收益矩阵 ⇒ 不存在「最优 β」，c = 0 只是中立。

三档一句话

  • 简单：明显球 86%，抖动 2.2 px，1.95 s ⇒ 期望 d′ ≈ 2.4（σ=1.0 时）
  • 普通：明显球 57%，抖动 4.5 px，1.75 s ⇒ 期望 d′ ≈ 1.8
  • 困难：明显球 24%，抖动 8.9 px，1.45 s ⇒ 期望 d′ ≈ 1.3
